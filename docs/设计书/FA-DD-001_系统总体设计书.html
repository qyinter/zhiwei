1. 概要

1.1 目的

知微是一套面向社区场景（QQ 群 / 频道、Telegram 群）的 AI 客服系统：接入真实会话，依据知识库作答，需要人工时转入人工队列，后台可查看全部会话并以机器人身份人工回复。本书描述整体架构、进程与模块划分、跨功能的设计决策与关键设计取舍。各功能细节见 FA-DD-002 ~ FA-DD-010。

1.2 范围

  • 一期（v0.1，本次实装）：初始化向导、管理员认证、QQ 官方机器人（WebSocket / Webhook）、Telegram（long polling）、企业微信接口预留、LLM 直连（OpenAI 兼容 / Anthropic）、知识库（BM25）、预检索 + 工具循环、转人工与超时恢复、后台（总览 / 会话 / 人工队列 / 知识库 / 体验台 / 系统设置）。
  • v0.2（2026-10-24 实装）：群运营——群消息时间线、主动回复、入群欢迎、入群审核（FA-DD-008）；反思沉淀——提炼、整理、升格（FA-DD-009）。
  • 2026-10-24 追加：知识库目录 / 批量导入 / 向量混合检索（FA-DD-005）、技能（SKILL.md 技能包，FA-DD-010）。
  • 2026-10-25 追加：图片识别、按群设置、问题排行、用量统计、运行日志。
  • 后续（规划）：业务插件工具（HTTP 工具，可作为技能的可执行部分）、企业微信适配器、多管理员与操作审计。见 4.6。

1.4 用语定义

用语定义
渠道（channel）消息来源平台：qqbot / telegram / wecom（预留）/ playground（后台体验台，虚拟渠道）
会话（conversation）渠道 × 聊天 × 用户。群里每个用户各一个会话，上下文互不串

转人工（handoff）会话进入人工接待态，自动回复暂停，直到后台「恢复自动」或超时
哨兵 __NO_ANSWER__模型判断无需回复时输出的固定串，回复闸门一律吞掉

2.2 技术要素

层选型理由
后端Go 1.23、gin、pgx/v5、coder/websocket、log/slog单二进制部署；长连接（QQ 网关）与并发会话天然适合 goroutine；不引 ORM，SQL 行为可见
前端Next.js 16（create-next-app 官方脚手架）、React 19、Tailwind v4、radix-ui、sonner、next-themes主流 React 栈，UI 组件与令牌按知微设计系统实现

LLMHTTP 直连：OpenAI Chat Completions 或 Anthropic Messages不依赖 Claude Code CLI / agent SDK；任意兼容端点（DeepSeek、通义、MiniMax、Kimi、vLLM、Ollama…）可用
UI 规范docs/设计规范/知微设计系统.html主色蓝 #0075FF、墨黑标题、Geist 字族、控件 8px / 卡片 16px 圆角、明暗双主题

2.3 前提条件・制约事项

  • env 只保留数据库连接串：ZHIWEI_DB_DSN（必填）与 ZHIWEI_HTTP_ADDR（可选，缺省 127.0.0.1:8080）；Next 侧可选 ZHIWEI_API_ORIGIN。管理员、LLM 凭据、渠道凭据、回复策略全部存 PG，经向导 / 后台修改，改配置不重启。
  • 单实例：Telegram 同一 token 只允许一个 getUpdates 消费者（第二个 409）；QQ WebSocket 网关一个分片一条连接；会话串行队列与登录限速都在进程内。水平扩展需先把这三处外置（二期）。
  • Go 服务默认只监听回环地址，由 Next 反代；QQ webhook 模式需要公网 HTTPS 时只暴露 Next（/webhook/* 已在 rewrites 中转发）。
  • QQ 官方机器人缺省只收 @ 消息；开放平台开通「接收所有消息」后可订阅群全量消息（GROUP_MESSAGE_CREATE）。回复优先被动回复（群 5 分钟 / 5 次，单聊 60 分钟 / 4 次），超窗自动改发主动消息（群：Bot 60/qpm、未认证 30/qpm，单群 20/qpm 且每天 1000 条）。

4. 功能详细

4.1 进程启动（S-01…）

  1. S-01 读 env（config.Load），缺 DSN 直接退出。
  2. S-02 连接 PG（5 秒 ping），执行内嵌迁移（store.Migrate：advisory lock 串行、checksum 防篡改、每文件一个事务）。
  3. S-03 加载全部设置分区（缺省值打底，库里字段覆盖），从 kb_chunks 重建检索索引。
  4. S-04 runtime.Apply：配置 LLM 客户端；若 setup.completed 为真，按开关启动渠道适配器。
  5. S-05 未初始化时生成 8 位数字口令并以 WARN 打印 setupCode=…。
  6. S-06 启动人工超时扫描（每分钟）与 HTTP 服务；SIGINT/SIGTERM 时优雅关闭（10 秒）并停掉全部适配器。

4.2 一条消息的处理链

sequenceDiagram
  participant P as 平台(QQ/TG)
  participant A as Adapter
  participant O as Orchestrator
  participant DB as PostgreSQL
  participant B as Brain
  participant L as LLM
  P->>A: 事件(WS Dispatch / Webhook / getUpdates)
  A->>O: Handle(Inbound)
  O->>O: 触发判定(@ / 私聊) + 群白名单
  O->>DB: UpsertConversation + AddMessage(入站去重)
  O->>O: 关键词命令(重置/帮助/人工) 或 人工中则静默
  O->>O: 入会话队列(运行中则并批)
  O->>B: Run(history, texts, quoted)
  B->>B: 预检索 kb.Search
  loop 最多 MaxToolRounds 轮
    B->>L: Chat(system 恒定, messages, tools)
    L-->>B: content / tool_calls
    B->>B: 执行 kb_search / transfer_to_human
  end
  B-->>O: reply / handoff / usage
  O->>DB: llm_calls、handoffs
  O->>A: Send(拆条, 首条引用原消息)
  O->>DB: AddMessage(out)

4.3 设置变更与热装配

  • 后台 PUT /api/settings → settings.Service.Save：校验 → 只写有变化的分区 → 更新内存快照 → 广播 → runtime.Apply。
  • Apply 由互斥锁串行化：先 Orchestrator.Configure 换 LLM 客户端与快照，再 Registry.Replace：先停旧适配器再起新的。正在进行的推理轮次使用旧快照跑完。
  • LLM 配置不完整时 Brain 为 nil：渠道照常收消息、落库、响应关键词命令，但跳过自动回复；总览页显示黄色告警。

4.4 关键设计取舍

选择没有采用的做法理由
internal/llm HTTP 直连 + internal/agent 自写工具循环拉起本地 agent CLI / agent SDK不依赖 CLI、MCP 子进程与 transcript 文件；历史由 messages 表重建；任意兼容端点可用
QQ 开放平台官方机器人 API v2OneBot v11 / NapCat 等第三方协议端官方通道，无需托管个人 QQ 账号；全量群消息需在开放平台开通「接收所有消息」，开通后主动回复与反思沉淀才有素材（FA-DD-008 / 009）
手写 Telegram Bot API 客户端（getUpdates / sendMessage）引入第三方 Bot 框架只用到少数接口，自写可控；按 UTF-16 偏移切 @、成功一次即恢复已连接状态
PostgreSQL + 内存 BM25（中文 bigram）+ 可选向量（独立 TEI 嵌入服务，bge-small-zh，向量存 PG REAL[]）SQLite + 向量扩展 + 进程内本地嵌入模型Go 进程保持纯 Go 无 native 依赖；嵌入服务不可用时退回纯关键词
system_settings 分区 KV + 初始化向导 + 管理员账号单行 JSON 配置 + env 播种 + 静态管理令牌env 只剩 DSN，其余配置都在后台改
conversations(channel, chat_id, user_id) + context_since + 空闲截断按会话键续接 + resume TTL按消息时间间隔截断，无额外状态，不会因 TTL 被反复刷新而失效，见 FA-DD-004
会话串行队列 + 运行中到达的消息并批无防抖，连发几条各答一次同一用户连发 N 条只答一次
直接函数调用（Handler 回调）事件总线（EventEmitter）Go 单进程无需事件总线

其他约定：system prompt 恒定、动态内容放 user 侧（吃 prompt cache）；用户文本定界符 + 剥离伪造定界符；整句匹配的关键词命令；__NO_ANSWER__ 哨兵；回复按标点拆条、只有首条引用；出错发兜底文案；人工超时自动恢复；所有外部调用都有硬超时；断线退避重连。
