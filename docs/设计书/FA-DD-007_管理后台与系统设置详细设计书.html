1. 概要

1.1 目的

提供一个管理后台：看运行状况、调试回答效果、修改全部配置且即时生效。

1.2 范围

后台外壳与导航、总览、体验台前端、系统设置（分区、校验、掩码、热装配）、UI 规范迁移。会话 / 人工队列 / 知识库页面见 FA-DD-005、FA-DD-006。

1.3 相关文档

FA-DD-001 ~ FA-DD-006；docs/设计规范/知微设计系统.html。

1.4 用语定义

见 FA-DD-001 1.4。

2. 前提

2.1 系统构成

Next.js 页面全部为客户端组件（"use client"），数据经 lib/api.ts 同源请求 /api/*；Next 仅负责静态外壳与 rewrites，不做 SSR 取数（避免 Next 服务端再带 cookie 转发一次）。

2.2 技术要素

  • Next.js 16 由官方 create-next-app 生成（App Router、src 目录、Tailwind v4、cacheComponents）；页面在构建期预渲染为静态外壳。
  • UI 规范：globals.css 按知微设计系统（docs/设计规范/知微设计系统.html）定义令牌，含语义色令牌 --ok / --warn / --crit 及其 soft 底；components/ui 提供 button / card / input / select / switch / dialog / alert-dialog / sheet / table / badge / skeleton / sonner / segmented-tabs 等基础组件，Badge 含 ok / warn / crit / accent / neutral 变体。
  • 全局约定：加载态 useDelayedLoading / useDelayedPending（超过 200ms 才显示）；分页每页 20 条；数字输入本地 string 草稿、失焦解析。

2.3 前提条件・制约事项

  • 设置整份读写：前端 GET 全部分区（密钥掩码）→ 本地编辑 → PUT 全部分区。服务端以当前值为底解码，未传的分区保持不变；setup 分区忽略。
  • 保存触发整套重装：已启用渠道会断开重连（QQ WS 会走一次 Identify），频繁保存会造成短暂离线。

4. 功能详细

4.1 总览（F-02）

  • 返回 {stats, channels, llm:{protocol, model, error}, kbChunks, brand}。
  • stats：会话数（不含体验台）、待人工数、今日咨询 / 自动回复（不含体验台）、今日模型调用 / 失败、今日输入 / 输出 token、知识文档数。今日缓存命中 token。「今日」= 浏览器时区（?tz=，IANA 名，缺省 UTC）当日零点起——库的时区通常是 UTC，按库切日会让东八区的「今日」从早上 8 点开始。服务端内嵌 time/tzdata，精简镜像也能解析时区。
  • 「今日 Token」卡片显示缓存命中率，点击进入用量统计。
  • channels 固定顺序 qqbot / telegram / wecom：已启用取适配器实时状态，未启用给占位。徽章：未启用 neutral、已连接 ok、有错误 crit、连接中 warn。
  • LLM 未就绪时页面顶部显示 warn 横幅并链接到设置页。

4.2 保存设置（F-04）

  1. S-01 以当前设置为底解码请求体（先克隆 agent.chats：encoding/json 解数组会就地覆写元素，否则校验失败也会改脏内存里的当前设置；groups 自带每次换新切片的 UnmarshalJSON）；请求体只带部分分区时其余分区不变；强制保留 setup；Unmask：仍含 •••• 的密钥字段还原为旧值。
  2. S-02 Validate（第 6 章）；失败 400 返回首条错误。
  3. S-03 逐分区 reflect.DeepEqual 比较，只 UPSERT 有变化的分区。
  4. S-04 更新内存快照并广播 → runtime.Apply（FA-DD-001 4.3）。
  5. S-05 返回保存后的掩码设置，前端替换本地状态并 toast。

4.3 密钥掩码

掩码字段：llm.apiKey、qqbot.appSecret、telegram.botToken、wecom.secret、wecom.encodingAesKey、embedding.apiKey。规则：空 → 空；≤4 字符 → ••••；否则 •••• + 后 4 位。回写时只要包含 •••• 即视为未修改。

4.4 设置页结构

分段标签：大模型（预设按钮 + 测试连接）/ 客服策略 / 向量检索（测试连接：返回耗时、维数与两组示例相似度）/ 群运营（主动回复、问题排行、入群欢迎、入群审核）/ 反思沉淀 / 品牌 / QQ 机器人 / Telegram / 企业微信（预留说明）/ 账号（改密）。表单组件与初始化向导共用（settings-forms.tsx），一处修改两处生效。页头一个主按钮「保存设置」（设计系统：一屏一个主按钮）。

4.5 体验台前端（F-06）

左侧对话（Enter 发送、Shift+Enter 换行、输入法组合中不触发），右侧「本轮详情」：模型、耗时、输入 / 输出 / 缓存命中 token、转人工提示、预检索命中（带分数）、工具调用（可展开结果）。「新对话」清空界面并让下一条以 reset=true 发送。输入框左侧可选图片，也可直接粘贴截图（最多 4 张、单张 10MB，前端读成 data URL 随请求发送）；回复下方标出「看了 N 张图」，上游拒收图片时标「模型拒收图片，已去图重试」。

会话抽屉：客户消息带图片且图片未过期时，显示缩略图（点开看缩放后的原图），正文里的「[图片]」占位不再重复；图片 30 天后清理，占位留着说明发过图。

4.6 视觉规范落地要点

  • 主色唯一：蓝 #0075FF（暗色 #4D9BFF）用于主按钮、链接、焦点、导航高亮；语义色只表状态。
  • 圆角两档：控件 8px（rounded-lg）、卡片 / 对话框 16px（rounded-2xl）；胶囊徽章全圆角。
  • 页标题 27px / 650 / −0.02em；kicker 用等宽小号大写；数据、ID、token、模型名用 Geist Mono + tabular-nums。
  • 品牌字标：「开」墨黑 +「元」品牌蓝 + 终端光标块（呼应设计系统 rail brand）。

4.7 用量统计（F-07）

  1. S-01 时间窗：浏览器时区下 days−1 天前的零点至今（days 1~90，页面提供今日 / 近 7 天 / 近 30 天）。
  2. S-02 返回 {from, days, usage:{totals, days[], byPurpose[], byModel[], tools[], errors[]}}：每组累计调用、失败、输入 / 输出 / 缓存命中 / 缓存写入 token、图片数、平均耗时；按天分组用 to_char(created_at AT TIME ZONE tz, 'YYYY-MM-DD')；工具统计展开 tool_names，给出调用次数与涉及轮数；最近 20 次失败的时间、用途、模型、错误。
  3. S-03 页面：四张统计卡（模型调用与失败率、输入 token 与缓存写入 / 图片数、缓存命中率 = 命中 ÷ 输入、输出 token 与平均耗时）；多天时显示每日 token 柱状图（单序列、单色，补齐无调用的日子，悬停看当天调用数、输入、命中率、输出、失败数）；按用途、按模型两张表；工具表（使用率 = 涉及轮数 ÷ 客服回复与主动回复的轮数）；最近失败列表。

4.8 运行日志（F-08）

  1. S-01 进程日志经 logbuf.Handler 包装：每条先进内存环形缓冲（2000 条），再交给原来的 stdout 文本 Handler。缓冲只在内存里，重启清空；完整日志仍以 stdout 为准。
  2. S-02 每条带进程内单调递增的 seq、时间、级别、消息与属性（含 With 预置的 mod 等，分组前缀用点连接）。
  3. S-03 接口按 after（只要 seq 更大的）、level（INFO / WARN / ERROR，及以上）、q（消息与属性键值的不区分大小写子串）过滤，每次最多 500 条，返回 {list, latest, capacity}。
  4. S-04 页面每 3 秒按 after = latest 增量拉取，前端最多留 2000 条、最新在上；可暂停刷新、清屏；切换级别或搜索词时从头重拉。错误行浅红底。
