1. 概要

1.1 目的

为客服回答提供依据：管理员在后台按目录维护 Markdown 文档（可从本地批量导入），保存即切块并重建检索索引；Agent 通过预检索与 kb_search 工具使用（FA-DD-004）。检索同时走关键词与语义两路，换个说法的提问也能命中。

1.2 范围

文档 CRUD、启停、目录、批量导入、切块规则、分词与打分、向量化与混合检索、检索测试。反思沉淀条目（approved）与文档块一起进入检索（FA-DD-009）。

1.3 相关文档

FA-DD-004（预检索与工具）、FA-DD-007（设置页「向量检索」标签）、FA-DD-009（沉淀条目与升格文档）。

1.4 用语定义

用语定义
块（chunk）检索粒度：≤500 字的正文片段，带所属文档标题与最近的 Markdown 标题
目录（path）文档所在目录，「/」分隔的多级路径，如「计费/退款」；空串为根目录。目录不单独建表，由文档的 path 推导
bigram中文连续汉字的相邻二字组，如「怎么充值」→ 怎么 / 么充 / 充值
嵌入服务把文本转成向量的 HTTP 服务，接口为 OpenAI 兼容的 POST {baseUrl}/embeddings
RRF倒数排名融合：每路结果按名次记 1/(60+名次)，同一块的两路得分相加后排序

2. 前提

2.1 系统构成

PG（kb_documents / kb_chunks，以及 kb_reflections 中 approved 的沉淀条目，来源名「人工沉淀」）为唯一事实源，向量也存在这两张表的 embedding 列里。kb.Index 是启用文档全部块的内存快照（含当前模型的向量），启动时与每次增删改后整体重建，检索期间用读锁、重建完成后原子替换。

向量由外部嵌入服务生成。缺省部署为 docker-compose 的 embed 服务：HuggingFace text-embeddings-inference + BAAI/bge-small-zh-v1.5（512 维），仅监听 127.0.0.1:8081。

2.2 技术要素

  • 关键词：纯 Go BM25（k1=1.2，b=0.75），中文 bigram + ASCII 词。
  • 向量：internal/embed 调 /embeddings，结果归一化为单位向量；余弦相似度 = 点积，进程内全量计算。
  • 不依赖 pgvector：向量存 REAL[]，客服知识库通常几十到几千块，全量点积毫秒级。

2.3 前提条件・制约事项

  • 为什么嵌入模型单独部署而不嵌进 Go 进程：Go 跑 ONNX 模型只能走 onnxruntime 的 CGO 绑定 + 自带分词器，会破坏纯 Go 单二进制与交叉编译。独立服务实测（arm64，bge-small-zh-v1.5）：常驻内存约 175MB、空闲 CPU ≈0、单条约 20ms、镜像 342MB，秒级就绪。
  • 嵌入服务可选：未开启或不可用时检索自动退回纯关键词，行为与 v0.2 一致。
  • 单篇文档 ≤2MB；标题 ≤200 字；目录路径 ≤255 字；单次导入 ≤50MB、≤1000 篇。

4. 功能详细

4.1 保存（F-03）

  1. S-01 path 规范化（CleanKBPath：\ 统一为 /，每段去首尾空白，去空段）；校验标题非空且 ≤200 字、路径 ≤255 字、正文 ≤2MB；enabled 缺省 true。
  2. S-02 kb.Split 切块（4.2）。
  3. S-03 单事务：新建 INSERT / 更新 UPDATE（不存在 404）→ 删除该文档旧块 → COPY 批量插入新块（新块 embedding 为空）。
  4. S-04 重建内存索引并唤醒向量化任务；返回文档（含 chunkCount），前端 toast「已保存，切分为 N 个检索块」。

4.2 切块规则

  • 按空行分段；以 # 开头的段视为标题：先结束当前块，标题文字成为后续块的 heading（标题行之后的同段文字归入正文）。
  • 段落累加到当前块，超过 500 字前先结束当前块。
  • 单段超 500 字：在后半段（250~500 字之间）找 。！？!?；; 或换行切，找不到则 500 字硬切。
  • 空文档：以标题作为唯一块（保证文档可被标题检索到）。

4.3 目录（F-06）

  • 目录树由前端按文档 path 组装：每级显示文档总数，可折叠；筛选框按「目录/标题」子串过滤（筛选时全部展开）。目录行悬停（触屏常显）出现：在此目录新建文档、导入到此目录、改名 / 移动。
  • 改名 / 移动：from 目录及其所有子目录整体换前缀到 to（to 为空 = 移到根目录，与已有目录同名即合并）。单条 UPDATE：path = from 改为 to，path 以 from/ 开头的替换前缀。
  • 目录不参与向量化文本，改名不需要重新向量化；BM25 索引文本包含目录，按目录名检索可命中。
  • 反思沉淀升格的文档统一放在「反思沉淀」目录（FA-DD-009）。

4.4 批量导入（F-07）

  1. I-01 请求：multipart 字段 files（可多个）、paths（与 files 一一对应的相对路径；浏览器选文件夹时为 webkitRelativePath，因 Go 解析 multipart 文件名会去掉目录）、prefix（导入到哪个目录下）、mode（overwrite 缺省 / skip）。请求体上限 50MB。
  2. I-02 .zip 在服务端展开（不落盘），条目按同样规则处理。zip 文件名合法 UTF-8 原样使用，否则按 GBK 解码（Windows 资源管理器打的包）。
  3. I-03 逐个文件：路径段以 . 开头或为 __MACOSX 的静默跳过；只收 .md / .markdown / .txt；正文去 UTF-8 BOM，不是 UTF-8 时按 GBK 再试（解出替换符视为失败）。
  4. I-04 文件所在子目录拼在 prefix 后成为文档目录，文件名去扩展名成为标题；同一批里目录 + 标题重复的，后出现的为准。
  5. I-05 单事务写入：同目录同标题已存在时，overwrite 覆盖正文（保留启用状态）、skip 跳过；否则新建（启用）。
  6. I-06 重建索引并唤醒向量化。未导入的文件与原因在 ignored 里返回，前端列表展示。

前端在提交前展示每个文件的最终「目录 / 标题」预览与总大小（超 50MB 禁止提交）；zip 只显示压缩包本身。

4.5 分词与关键词打分

  • 分词：汉字段 → bigram（单字段出单字）；字母数字及 _ - . 组成的词 → 小写整词；其余字符为分隔。例：API Key 怎么充值? → api | key | 怎么 | 么充 | 充值。
  • 每块的索引文本 = 目录 + 文档标题 + 小节标题 + 正文。
  • BM25：Σ idf(t) · f·(k1+1) / (f + k1·(1 − b + b·len/avgLen))，idf = ln(1 + (N − df + 0.5)/(df + 0.5))，查询词去重。
  • 相对阈值：低于最高分 30% 的结果丢弃——避免只撞上一个常见二字组（如「价格」）的块被塞给模型。

4.6 向量化（F-09）

  • 向量化文本：块 = 文档标题 + 小节标题 + 正文（换行连接）；沉淀条目 = FAQ 文本。单条超过 2000 字先截断，TEI 以 --auto-truncate 按模型上限（512 token）再截。
  • 待处理 = 启用文档的块与 approved 沉淀条目中，embedding 为空或 embed_model ≠ 当前模型名的行。模型名即向量版本：设置里改模型，全部重算。
  • 任务被唤醒（保存 / 删除 / 导入 / 改名 / 沉淀变更后的重建、设置切换模型）或每分钟一次：每批 32 条送嵌入服务，按 id 回填 embedding, embed_model（期间被删除或重切的块匹配不上，自然跳过）；本轮有回填则重建快照。
  • 嵌入服务出错：本轮放弃，下轮重试；错误记入状态（F-01 的 embedding.lastError），首次出错与恢复各记一条日志。

4.7 混合检索（F-05 / Agent 共用）

  1. H-01 若开启向量检索且快照里已有向量：向量化问句（超时 3 秒）。失败则记错误、本次只走关键词。
  2. H-02 关键词一路：BM25 排序 + 30% 相对阈值（4.5）。
  3. H-03 向量一路：与每个维度一致的块向量做点积，≥ embedding.minScore（缺省 0.5）的按相似度排序。
  4. H-04 只有关键词一路时 score = BM25 分（与 v0.2 完全一致）；两路都有时按 RRF（k=60）融合，score = 融合分。每条结果另带 keyword（BM25 分）与 vector（余弦），未命中该路为 0。
  5. H-05 截取 topK（检索测试缺省 5，上限 20；Agent 用 agent.kbTopK）。给模型的来源写作「目录/标题 / 小节」。

实测（bge-small-zh-v1.5）：「怎么充钱」对「充值方法…」0.71、对「API Key…」0.22；「钱能退吗」对「退款…」0.65；「今天天气怎么样」「你们是做什么的」在 0.5 下限下无召回。

4.8 后台页面（F-10）

  • 状态条：未开启向量检索时提示「当前只按关键词检索…」并链接到 /admin/settings?tab=embedding；开启后显示模型名与「已向量化 x / y 块」，未完成时显示进度条并每 3 秒静默刷新；嵌入服务异常时红字显示原因。
  • 编辑器：目录输入框（候选为已有目录）+ 标题。
  • 检索测试（对话框）：结果显示「目录/标题 / 小节」、「关键词 x」「语义 x」两个徽章与正文前 4 行；点结果关闭对话框并打开对应文档（沉淀条目不可点）。

4.9 停用与删除（F-03/F-04）

停用的文档保留内容、块与向量，但不进入索引、不参与向量化；删除级联删除块。两者都触发索引重建。

4.10 异常系

  • E-01 索引重建失败（DB 异常）：记 error 日志，继续使用旧索引；保存接口仍返回成功（数据已落库，下次重建自愈）。
  • E-02 嵌入服务不可用：检索退回关键词，向量化下轮重试（4.6）；已有向量保留，服务恢复后自动重新参与。
