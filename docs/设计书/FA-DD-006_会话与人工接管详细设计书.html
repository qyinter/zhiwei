1. 概要

1.1 目的

记录每个用户的完整对话，让管理员能看到机器人答了什么；AI 无法可靠处理时把会话交给人工，人工直接在后台回复用户，处理完一键恢复自动客服。

1.2 范围

会话 / 消息模型与去重、会话列表与详情、转人工的三种入口、人工回复、恢复（手动 / 超时）、上下文重置。

1.3 相关文档

FA-DD-003（被动回复窗口）、FA-DD-004（命令、工具、历史）。

1.4 用语定义

用语定义
会话状态active（自动回复）/ handoff（人工接待，自动回复暂停）
上下文起点（context_since）早于它的消息仍可在后台查看，但不再喂给模型
消息方向in 用户 / out 机器人 / human 后台人工

2. 前提

2.1 系统构成

写入侧在编排器（入站、回复、工单）；读取侧为后台 REST。会话详情抽屉每 5 秒轮询，人工队列与总览每 15 秒轮询（一期不做推送）。

2.2 技术要素

入站去重用部分唯一索引 + ON CONFLICT DO NOTHING；工单开关用条件更新保证幂等。

2.3 前提条件・制约事项

  • 会话键 = (channel, chat_id, user_id)：群里每个用户一个会话，上下文不串；同一用户在不同群是不同会话。
  • 人工回复经原渠道以机器人身份发出：QQ 借最近一条入站消息做被动回复，超过 5 分钟（或该消息已回复 5 次）自动改发主动消息，受主动消息频控、用户可关闭接收（抽屉内有提示）；TG 无此限制。
  • 一期无「转人工通知」推送；管理员需关注后台人工队列 / 总览「待人工」数。二期可接入通知渠道。

4. 功能详细

4.1 入站落库与去重

  • AddMessage：INSERT … ON CONFLICT (conversation_id, platform_msg_id) WHERE direction='in' AND platform_msg_id<>'' DO NOTHING RETURNING id；无返回行 → ErrDuplicate，编排器静默结束。覆盖 QQ webhook 超时重推、WS Resume 补发、TG 重启后重复拉取。
  • 入站同时刷新 last_message_at 与 last_inbound_msg_id；出站只刷新 last_message_at。

4.2 转人工（F-03）

stateDiagram-v2
  active --> handoff: 用户「人工」/ transfer_to_human
  handoff --> handoff: 再次「人工」（回「正在处理中」）
  handoff --> active: 后台恢复自动 / 超时
  active --> active: 重置（推进 context_since）
  1. S-01 单事务：UPDATE conversations SET status='handoff' WHERE id=? AND status<>'handoff'；影响 0 行 → 已在人工中，不重复建单。
  2. S-02 影响 1 行 → 插入 handoffs(reason, summary)。关键词入口 reason=「客户主动要求人工」、summary=原文；模型入口取工具参数。
  3. S-03 关键词入口由系统回固定话术；模型入口由模型在回复中告知客户（工具结果有指示）。
  4. S-04 handoff 期间：用户消息照常落库（后台可见），不入推理队列；排队中的轮次开始前重读状态，已转人工则放弃。

4.3 人工回复（F-04）

  1. S-01 文本 trim 后非空；体验台会话前端禁用。
  2. S-02 以 last_inbound_msg_id 为 ReplyTo 拆条发送（规则同 FA-DD-004 4.8），每段以 direction=human、sender_name=管理员用户名 落库。
  3. S-03 发送失败 → 502「发送失败：{平台错误}」。
  4. 人工回复在后续历史中以「（人工客服）…」的助手消息出现；恢复自动时 context_since 推进，因此不会被模型续写。

4.4 恢复自动（F-05/F-06）

  1. S-01 单事务：关闭该会话全部 open 工单（resolved_at=now，resolved_by=管理员，超时为 NULL）→ status='active', context_since=now()。
  2. S-02 原状态为 handoff 且非体验台：向用户发「已恢复自动客服，有问题可以继续问我。」（QQ 超窗会发送失败，仅记日志）。
  3. 超时扫描：每分钟查 status='open' AND created_at < now − handoffTimeoutMin 的会话逐个恢复；handoffTimeoutMin=0 关闭。

4.5 后台界面（F-01/F-02/F-08）

  • 会话列表：关键词（用户名 / 用户 ID / 群名 / 群 ID，回车生效）、渠道、状态筛选；表头等宽小号、数字列右对齐等宽（设计系统「表格」）；超过一页显示「第 x/y 页 · 共 n 条」。
  • 详情抽屉：气泡区分用户（白底描边）/ 机器人（accent-soft）/ 人工（warn-soft）；上下文起点之前的消息半透明；底部人工回复框（⌘/Ctrl + Enter 发送），人工中显示「处理完毕，恢复自动」，否则显示「重置上下文」。
  • 人工队列：分段标签 待处理 / 已处理 / 全部，卡片展示用户、渠道、状态、时间、摘要与原因，点击打开同一抽屉。

6. 错误一览

HTTPmessage
400回复内容不能为空
502发送失败：{平台错误}
404记录不存在

对用户的固定话术：「已为你转接人工客服，请稍候，客服会尽快回复你。期间自动回复暂停。」「人工客服正在处理中，请耐心等待。」「已恢复自动客服，有问题可以继续问我。」

7. 配置项

agent.handoffTimeoutMin：人工接待超过该分钟数无人处理则自动恢复，0 不恢复。
