1. 概要

1.1 目的

把各平台的事件与发送 API 翻译成平台无关的 Inbound / Outbound，让客服编排（FA-DD-004）不感知平台差异；新增渠道只需实现一个接口。

1.2 范围

适配器契约与注册表、QQ 官方机器人、Telegram、企业微信接入点。触发规则（@、白名单、命令）不在适配器内，见 FA-DD-004。

1.3 相关文档

FA-DD-001、FA-DD-004、FA-DD-006（人工回复经渠道发送）、FA-DD-007（渠道设置表单）。

1.4 用语定义

用语定义
被动回复QQ：带被回复事件的 msg_id 发送（群 5 分钟内、每条最多 5 次；单聊 60 分钟、4 次），不计主动消息频控
openidQQ 群 / 单聊里平台给出的匿名 ID（group_openid、member_openid、user_openid），每个机器人看到的值不同，不是 QQ 号
intentsQQ 网关订阅位

2. 前提

2.1 系统构成

runtime.Apply ──► Registry.Replace([qqbot.Adapter?, telegram.Adapter?], Orchestrator.Handle)
                        │
     Adapter.Start ─────┤  后台 goroutine：QQ 网关会话循环 / TG getUpdates 循环
     平台事件 ──► parse ─┴► Handler(Inbound)      （适配器不等待处理结果）
     Orchestrator ──► Registry.Send(channel, Outbound) ──► Adapter.Send
     平台回调 /webhook/{name} ──► Registry.ServeWebhook ──► WebhookAdapter.ServeWebhook

2.2 技术要素

  • QQ WebSocket：github.com/coder/websocket；Webhook 验签：标准库 crypto/ed25519。
  • Telegram：标准库 net/http，无 SDK。

2.3 前提条件・制约事项

  • QQ 官方机器人在群 / 公域频道只收得到 @ 它的消息，收不到群内其他人的聊天；拿不到 QQ 号与昵称（群内只有 openid）。因此会话列表中 QQ 用户显示为 openid。
  • QQ 被动回复窗口过期或次数用尽（错误码 40034005 / 40034128）时，Send 去掉 msg_id / msg_seq 重发为主动消息；主动消息受频控（群：Bot 60/qpm、未认证 30/qpm，单群 20/qpm、每天 1000 条），用户关闭「允许主动发送」时失败。
  • QQ 消息中的 URL 需在开放平台报备域名，否则发送可能被拒——知识库 / 口径中给 QQ 用户的链接应使用已报备域名。
  • Telegram 同一 token 只能一个进程轮询；服务器无法直连 api.telegram.org 时把「API 地址」改为自建 Bot API Server 或反代。

4.2 QQ 官方机器人（F-03 ~ F-06）

4.2.1 鉴权

  • POST https://bots.qq.com/app/getAppAccessToken {"appId","clientSecret"} → {"access_token","expires_in"}（expires_in 为字符串秒数，解析失败按 7200）。
  • OpenAPI 基址 https://api.sgroup.qq.com，沙箱 https://sandbox.api.sgroup.qq.com；请求头 Authorization: QQBot {token}。
  • 非 2xx：错误串 QQ API {method} {path}: HTTP {status} code={code} {message}，原样进日志与状态。
  • Start 先换一次 token：凭据错误立即在状态中可见（webhook 模式下直接返回错误）。

4.2.2 WebSocket 网关

  1. S-01 GET /gateway 取 wss 地址并连接（读上限 4MB）。
  2. S-02 读 op=10 Hello，取 heartbeat_interval（缺省 40s）。
  3. S-03 有 session_id → op=6 Resume {token, session_id, seq}；否则 op=2 Identify {token:"QQBot …", intents, shard:[0,1]}。
  4. S-04 心跳 goroutine 按间隔发 op=1，d 为最近序号（首次 null）。
  5. S-05 读循环：每次读超时 = 3 个心跳周期（平台侧假死时 Read 不会自己返回）；op=0 READY 记 session_id 并标记已连接，RESUMED 标记已连接，其余事件分发解析。
  6. S-06 op=7 → 断开重连（保留 session 走 Resume）；op=9 → 丢弃 session 重新 Identify，并提示检查 intents 权限。
  7. S-07 外层循环退避 1s 起倍增、上限 60s；本次会话曾就绪则退避重置为 1s。
订阅开关intents 位事件

4.2.3 Webhook

  • 签名密钥：AppSecret 反复拼接到 ≥32 字节取前 32 字节作 Ed25519 seed（官方算法）。
  • op=13 回调地址验证：对 event_ts + plain_token 签名，返回 {"plain_token","signature":hex}。
  • 其他请求：校验头 X-Signature-Ed25519（hex，64 字节）与 X-Signature-Timestamp，消息 = timestamp + 原始 body；失败 401 invalid signature。
  • op=0 事件分发后返回 {"op":12}。分发是同步调用 Handler，但 Handler 只做落库与入队，推理异步，响应在毫秒级。
  • 平台超时重推同一事件时，由 messages 入站唯一索引去重（FA-DD-006）。

  • 正文：剥掉 <@!?ID>（频道 <@!数字>、全量群消息 <@member_openid> / <@all>）并 trim。Mentioned：@ 事件与单聊恒 true；GROUP_MESSAGE_CREATE 看 mentions[] 中 is_you，或 bot=true 且 ID 等于 READY 下发的机器人 ID。author.bot=true（机器人自己 / 其他机器人）丢弃。
  • 全量模式下同一条 @ 消息可能以两种事件各推一次，由入站唯一索引（FA-DD-006 4.1）去重。
  • 图片：消息事件 attachments[] 中 content_type 为 image/*（或为空但文件名是图片扩展名）的附件转为 Images；附件地址不带协议头时补 https://（// 开头补 https:）。只发图片的消息 content 为空格，Text 为空。语音、视频、文件附件不处理。
  • atUser=true 且为群聊时，拆条后的第一条正文前加 <qqbot-at-user id="{member_openid}" />（官方「文本交互」文档的格式；2026-10-24 实测主动消息里显示为原文，缺省关闭）。
  • ReviewJoin：POST /v2/groups/{group}/approval_join_request/{member} {op: approve|decline, join_request_id, reject_reason}（机器人需是群管理员，60 QPM）。
  • Telegram：消息的 new_chat_members 转为 member_join 事件（跳过机器人）；群消息附带 SenderRole。
  • 引用回复：Quote=true 时带 message_reference:{message_id}。群聊 / 单聊的 message_id 不是 msg_id，而是入站事件 message_scene.ext 里的 msg_idx=REFIDX_…（适配器按 msg_id 缓存 2 小时，进程内）；频道用消息 ID。取不到索引就不带；平台以 4xx 拒收引用时去掉引用重发一次。事件未带 msg_idx 时记一次 info 日志。
  • 发送体 {content, msg_type:0, msg_id, msg_seq}；频道 / 私信不带 msg_type 与 msg_seq。同一 msg_id 下多条回复必须 msg_seq 不同，否则平台按重复消息丢弃：编排器以毫秒时间低位 ×10 + 序号生成（FA-DD-004）。

4.3 Telegram（F-07）

  1. S-01 Start：getMe（15s 超时）取 bot id 与 username，失败返回错误（token 无效时立刻可见）。
  2. S-02 轮询：getUpdates{offset, timeout:30, allowed_updates:["message"]}，HTTP 客户端超时 45s。失败退避 1s~60s；任意一次成功即把状态置回已连接（否则一次失败后会永远显示断开）。
  3. S-03 offset 只在进程内推进（处理完一条即 update_id+1）。重启后从平台未确认的更新继续，可能重复的少量消息由入站唯一索引去重。
  4. S-04 解析：文本取 text，没有则取 caption（此时 @ 实体取 caption_entities）；图片取 photo 里不超过 10MB 的最大尺寸，以及 mime 为 image/* 的 document，被回复消息里的图片也带上（下载时先 getFile 换 file_path，再 GET {apiBase}/file/bot{token}/{file_path}）。文本与图片都没有的消息、机器人自己的消息忽略。私聊（开关可关）直接触发；群（group / supergroup）判定 @：
    • mention 实体：按 UTF-16 码元切出 @name，与 bot username 忽略大小写比较；
    • text_mention 实体：user.id 等于 bot id；
    • 回复机器人的消息（reply_to_message.from.id == bot id）。
    命中的实体从后往前删掉，保持前面实体偏移不变。被回复消息的文本进 Quoted。频道（channel）类型忽略。
  5. S-05 发送：sendMessage{chat_id, text, reply_parameters:{message_id, allow_sending_without_reply:true}}，单条超过 4096 字硬切，仅首段引用；每次调用 20s 超时。Format=markdown 时先渲染为 HTML、带 parse_mode:"HTML" 与 link_preview_options:{is_disabled:true} 整条发送；HTML 超过 4096 字，或平台报 can't parse entities，改发纯文本（4.6）。

4.4 企业微信（F-08，预留）

  • 设置分区 channel.wecom：CorpID、AgentID、Secret、Token、EncodingAESKey 已定义并参与掩码；settings.Validate 禁止启用（企业微信渠道尚未开放，请保持关闭）。
  • 实装步骤（写在 internal/channel/wecom/wecom.go 包注释）：
    1. 实现 channel.WebhookAdapter：GET 回调 URL 验证（msg_signature 校验 + AES 解密 echostr 原样返回）；POST 收加密 XML，解密后转 Inbound（应用消息：private / FromUserName；群机器人：group），5 秒内返回空串、处理异步。
    2. Send：gettoken（corpid + secret，7200s 缓存）→ /cgi-bin/message/send；无被动回复窗口，忽略 ReplyTo。
    3. runtime.Apply 按开关装配，删除 Validate 中的禁用分支；前端设置页替换占位说明为表单。
  • 编排器、会话、后台均无需改动——这是适配器契约的验收标准。

4.5 异常系

  • E-01 QQ token 获取失败：状态 lastError 为 获取 access_token 失败: code=… …；websocket 模式继续退避重试。
  • E-02 QQ op=9：lastError 会话失效（检查 intents 权限是否已在开放平台开通）——常见于未开通群 / 频道权限却勾选了对应订阅。
  • E-03 TG 409（另一实例在轮询）：退避重试并显示错误，不退出进程。
  • E-04 发送失败：编排器记 error 日志并停止发送本轮剩余分段，已发分段照常落库。

4.6 回复格式渲染

Outbound.Format：空 = 纯文本原样；markdown = 回复用精简 Markdown（channel/markdown.go），渠道发送前渲染；qqmarkdown = QQ 原生 Markdown（入群欢迎模板，可含 <qqbot-at-user> 等标签），只有 QQ 群聊 / 单聊按 Markdown 消息发，其他按原文。
